**About this endpoint**

**What this endpoint does**

The partner of the deprecated `/sign` call: it checks that a signature made by `/sign` matches the given text, using the key manager's own signing key (KERNEL / SIGN). Older callers use it to confirm a response or document really came from MOSIP and was not changed.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "signature": "Zm9vYmFy...",
    "data": "Test data",
    "timestamp": "2026-11-10T10:00:00.000Z"
  }
}
```
All three fields are required; `timestamp` must use the `yyyy-MM-ddTHH:mm:ss.SSSZ` format (the one `/sign` returns), but the code does not use its value (row _006).

On success:
```json
{
  "response": { "status": "success", "message": "Validation Successful" },
  "errors": null
}
```
A signature that does not match returns `KER-CSS-101` (`Validation Unsuccessful`) in `errors[]`. A signature that cannot be read at all returns HTTP 500 with `KER-KMS-500`. Missing or badly formatted fields return `KER-KMS-005`.

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
