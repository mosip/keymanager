**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Turns a person's UIN into a partner-specific "token ID". The same person always gets the same token ID for the same partner, but a different one for every other partner, so partners can recognise a returning person without ever seeing the UIN and cannot match people across each other. Nothing is stored — the value is recalculated on every call.

**Request & response**

A plain `GET` with the UIN and partner code in the path:
```
GET /v1/keymanager/tokenid/2345678901/PARTNER001
```
On success:
```json
{ "response": { "tokenID": "471295839104857362910485736291048573" }, "errors": null }
```
If the UIN or partner code is blank, the response is HTTP 200 with `errors[0].errorCode` = `KER-TIG-010` (`UIN and partner code cannot be empty`). The UIN is not checked against any register.

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, ID_AUTHENTICATION and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.

<summary>Technical details (automation + verification notes)</summary>

- Handler: `TokenIDGeneratorController.generateTokenID` (TokenIDGeneratorController.java:38-46); roles from `mosip.role.keymanager.getuinpartnercode` (application-local.properties:177).
- Algorithm: `TokenIDGenerator.generateTokenID` (:27-36) — `uinHash = SHA-256(uin + uinSalt)`, `hash = SHA-256(partnerSalt + partnerCode + uinHash)`, then `new BigInteger(hash.getBytes()).toString()` cut to 36 digits. The salts come from the environment config, so expected values are only comparable within one environment.
