**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Lists every certificate the key manager has ever held for an application (or for one of its reference IDs) — the current one and the older, expired or revoked ones. It is used where data signed or encrypted with an older key still has to be checked, so callers need the whole history and not only the current certificate.

**Request & response**

A plain `GET` with query parameters:
```
GET /v1/keymanager/getAllCertificates?applicationId=REGISTRATION&referenceId=
```
`applicationId` is required; `referenceId` is optional (leave it out or empty for the master key).

On success:
```json
{
  "response": {
    "allCertificates": [
      {
        "certificateData": "-----BEGIN CERTIFICATE-----\n...",
        "issuedAt": "2026-11-10T10:00:00.000Z",
        "expiryAt": "2029-11-09T10:00:00.000Z",
        "keyId": "base64url key identifier"
      }
    ]
  },
  "errors": null
}
```
The list is ordered by when each key was generated. An app ID that has no keys (even one with no key policy) returns an empty list rather than an error. A missing `applicationId` parameter returns `KER-KMS-005`.

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration) — the same list as getCertificate. Anyone else is refused. See README.md § How authentication works in this module.

<summary>Technical details (automation + verification notes)</summary>

- Handler: `KeymanagerController.getAllCertificates` (KeymanagerController.java:244-254); it reuses `mosip.role.keymanager.getgetcertificate` (application-local.properties:157) — there is no separate role property.
- Service: `KeymanagerServiceImpl.getAllCertificates` (:1274-1306). Empty reference ID, `KERNEL`+`SIGN` and the EC sign reference IDs read certificates from the HSM (:1308-1323); other reference IDs read the DB store (:1325-1344) and skip aliases with no stored certificate. Neither path checks the key policy (row _005).
- `keyId` is the alias's unique identifier converted from hex to base64url (`SignatureUtil.convertHexToBase64`).
