**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Adds a visible digital signature to a PDF document using a key held by the key manager, and can password-protect the result. MOSIP uses it to sign documents such as UIN cards and acknowledgement letters so anyone opening them can see they came from MOSIP and were not altered.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "applicationId": "KERNEL",
    "referenceId": "SIGN",
    "timeStamp": "2026-11-10T10:00:00.000Z",
    "data": "JVBERi0xLjQK...",
    "lowerLeftX": 10,
    "lowerLeftY": 10,
    "upperRightX": 200,
    "upperRightY": 60,
    "reason": "automation test",
    "pageNumber": 1,
    "password": "Test@123"
  }
}
```
`applicationId`, `timeStamp`, `data` (the PDF in base64) and `reason` are required; the four coordinates place the signature box on `pageNumber` and must not be negative; `password` is optional.

On success:
```json
{
  "response": { "data": "JVBERi0xLjQK..." },
  "errors": null
}
```
`data` is the signed PDF in URL-safe base64. Failures come back in `errors[]`, e.g. `KER-KMS-005` (missing or invalid field), `KER-KMS-012` (no key yet), `KER-KMS-020` (signing not allowed for that app/reference pair), `KER-KMS-500` (the file could not be read or signed).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Unlike the other signing endpoints, an app's key-policy user restriction is not applied here (row _008). See README.md § How authentication works in this module.
