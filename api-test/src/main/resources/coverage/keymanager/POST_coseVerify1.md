**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Checks a COSE_Sign1 message (the compact binary signature made by `/coseSign1`): was it signed by the expected key, and has nothing been changed since? Optionally it also checks whether the signing certificate chains up to a trusted authority. It is the partner of `/coseSign1`.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "coseSignedData": "d28445a101390100a0...",
    "applicationId": "",
    "referenceId": "",
    "certificateData": "",
    "isCOSETagIncluded": true,
    "validateTrust": false,
    "domain": ""
  }
}
```
`coseSignedData` (the hex string from `/coseSign1`) is required. The key used to check it is, in order: a certificate inside the message, else `certificateData`, else the key named by `applicationId`/`referenceId` (empty means KERNEL/SIGN). `isCOSETagIncluded` = false accepts a message signed with `includeCOSETag` = false. `validateTrust` + `domain` add a trust-chain check.

On success:
```json
{
  "response": { "signatureValid": true, "message": "Validation Successful", "trustValid": "TRUST_NOT_VERIFIED" },
  "errors": null
}
```
A wrong signature gives `signatureValid` = false and `Validation Failed`. `trustValid` is `TRUST_NOT_VERIFIED`, `TRUST_NOT_VERIFIED_NO_DOMAIN`, `TRUST_CERT_PATH_VALID` or `TRUST_CERT_PATH_NOT_VALID`. Failures come back in `errors[]`, e.g. `KER-KMS-005` (missing data), `KER-SIG-114` (not hex), `KER-CWS-121` / `KER-SIG-120` (tag expected / not expected), `KER-JWS-107` (certificate expired), `KER-KMS-012` (no key yet).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN, RESIDENT and CREDENTIAL_ISSUANCE (default configuration). Anyone else is refused. There is no per-app key policy check: verifying uses only public certificates. See README.md § How authentication works in this module.
