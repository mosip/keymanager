**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Returns the public half of the key manager's own "client crypto" signing key. Anyone who gets a signature from `POST /v1/keymanager/cssign` uses this key to check it (for example through `POST /v1/keymanager/csverifysign`). The name says "TPM" because the same code runs on registration-client machines with a hardware TPM; on a server pod there is normally no TPM, and the service falls back to a software RSA-2048 key pair it creates on first use (local mode). In local mode the signing and encryption public keys are the same key.

**Request & response**

```json
{
  "id": "string", "version": "string", "requesttime": "2026-11-10T10:00:00.000Z", "metadata": {},
  "request": { "serverProfile": "DEV" }
}
```
On success:
```json
{ "response": { "publicKey": "MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA..." }, "errors": null }
```
`serverProfile` must be non-blank but its value is not used. `publicKey` is URL-safe Base64 without padding: an X.509 public key in local mode, a TPM public-area blob with a real TPM.

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
