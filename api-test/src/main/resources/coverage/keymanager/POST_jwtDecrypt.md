**What this endpoint does**

Decrypts a JSON Web Encryption (JWE) token that was encrypted with one of the key manager's keys — typically one made by `/jwtEncrypt`. The token says which key it was made for (its `kid`); the key manager finds that key, checks it belongs to the app and reference ID named in the request, and returns the content.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": { "applicationId": "REGISTRATION", "referenceId": "REF01", "encData": "<JWE compact string>" }
}
```
All three fields are required.

On success:
```json
{ "response": { "data": "<base64url of the decrypted content>", "timestamp": "2026-11-10T10:00:00.000Z" }, "errors": null }
```
Failures come back in `errors[]`, e.g. `KER-KMS-005` (missing field), `KER-CRY-011` (signing key named), `KER-CRY-015` (not a valid or altered JWE), `KER-KMS-024` (JWE belongs to another app), `KER-KMS-025` (key not held).

**Who can call it**

By default ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT. Anyone else is refused. See README.md § How authentication works in this module.
