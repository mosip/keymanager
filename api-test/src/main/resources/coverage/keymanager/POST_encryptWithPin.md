**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Encrypts a piece of text with a key made from a PIN the caller chooses. Nothing is stored in the key manager: whoever later has the ciphertext and the same PIN can get the text back with `/decryptWithPin`. It is used, for example, to protect data a user can unlock with their own PIN.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": { "data": "hello world", "userPin": "A1234" }
}
```
Both fields are required and must not be blank. `data` is plain text (not base64).

On success:
```json
{ "response": { "data": "<base64url: salt + nonce + ciphertext>" }, "errors": null }
```
A missing field returns `KER-KMS-005` in `errors[]`.

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
