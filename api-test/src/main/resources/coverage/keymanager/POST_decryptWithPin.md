**About this endpoint**

**What this endpoint does**

Gets back the text that `/encryptWithPin` encrypted, given the same PIN. The key manager keeps nothing for these calls: the key is rebuilt from the PIN and the salt stored inside the ciphertext, so a wrong PIN simply fails.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": { "data": "<base64url ciphertext from /encryptWithPin>", "userPin": "A1234" }
}
```
Both fields are required and must not be blank.

On success:
```json
{ "response": { "data": "hello world" }, "errors": null }
```
`data` is the original plain text. Failures come back in `errors[]`, e.g. `KER-KMS-005` (missing field), `KER-CRY-003` (not base64url), `KER-FSE-004` (wrong PIN or altered ciphertext).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
