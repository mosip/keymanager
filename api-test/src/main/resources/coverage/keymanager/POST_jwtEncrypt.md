**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Wraps a JSON payload (or an already-signed JWS) in a JSON Web Encryption (JWE) token, using either the key of an application and reference ID held by the key manager, or a certificate the caller supplies (for example a partner's). The JWE can then be sent to whoever holds the matching private key — for the key manager's own keys, `/jwtDecrypt` opens it.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "applicationId": "REGISTRATION",
    "referenceId": "REF01",
    "data": "eyJuYW1lIjoidGVzdCJ9",
    "enableDefCompression": true,
    "includeCertificate": false,
    "includeCertHash": false,
    "jwkSetUrl": "https://example.org/.well-known/jwks.json",
    "x509Certificate": "<optional PEM certificate to encrypt for>"
  }
}
```
`data` is required: base64url of JSON text, or a JWS string. Without `x509Certificate`, `applicationId` and a non-empty `referenceId` are needed. The flags add the `zip`, `x5c`, `x5t#S256` and `jku` header entries; compression is on by default, the others off.

On success:
```json
{ "response": { "data": "<compact JWE>", "timestamp": "2026-11-10T10:00:00.000Z" }, "errors": null }
```
Failures come back in `errors[]`, e.g. `KER-KMS-005` (missing data), `KER-CRY-003` (not base64url), `KER-CRY-013` (not JSON), `KER-CRY-011` (no reference ID, signing key, or key not 2048-bit), `KER-KMS-002` (unknown app ID).

**Who can call it**

By default ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT. Anyone else is refused. See README.md § How authentication works in this module.
