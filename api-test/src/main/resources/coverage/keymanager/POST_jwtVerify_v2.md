**About this endpoint**

**What this endpoint does**

Version 2 of jwtVerify: checks a JSON Web Signature and says whether it is genuine. The difference from v1 is the optional trust check — v2 uses the whole certificate chain carried in the token header (leaf, intermediates, root) when deciding whether the signer is trusted for a partner domain, instead of only the signing certificate.

**Request & response**

The request and response are the same as jwtVerify:
```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "jwtSignatureData": "eyJ4NWMi....",
    "actualData": "",
    "applicationId": "",
    "referenceId": "",
    "certificateData": "",
    "validateTrust": false,
    "domain": ""
  }
}
```
```json
{
  "response": { "signatureValid": true, "message": "Validation Successful", "trustValid": "TRUST_NOT_VERIFIED" },
  "errors": null
}
```
A signature that does not match gives `signatureValid` = false and `message` = `Validation Failed`. Asking for a trust check on a token with no certificate chain in its header currently fails (row _006).

**Who can call it**

The same roles as jwtVerify: ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). See README.md § How authentication works in this module.
