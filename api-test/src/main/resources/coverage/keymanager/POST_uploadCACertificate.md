**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Adds a CA or sub-CA certificate to the key manager's trust store for one partner domain (`AUTH`, `DEVICE`, `FTM` or `TRUST_CA` by default). Partner certificates are later accepted only if they chain up to a CA uploaded here for the same domain. A self-signed certificate is stored as a root; any other certificate is accepted only if its root is already in the domain.

**Request & response**

```json
{
  "id": "string", "version": "string", "requesttime": "2026-11-10T10:00:00.000Z", "metadata": {},
  "request": {
    "certificateData": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----",
    "partnerDomain": "AUTH"
  }
}
```
`certificateData` is one PEM certificate, or a base64 p7b bundle with several. On success:
```json
{ "response": { "status": "Upload Success.", "timestamp": "2026-11-10T10:00:01.000Z" }, "errors": null }
```
With a bundle, `Partial Upload Success.` means some certificates were skipped and `Upload Failed.` that none was stored. The new certificate's ID is not returned; find it with getCaCertificates. For a single certificate, failures come back in `errors[]` with HTTP 200, e.g. `KER-PCM-003` (already in this domain), `KER-PCM-004` (expired), `KER-PCM-005` (root not uploaded), `KER-PCM-007` (not version 3), `KER-PCM-011` (domain not allowed), `KER-PCM-017` (less than 12 months left), `KER-PMS-020` (starts in the future), `KER-KMS-005` (empty field).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN and PMS_ADMIN (default configuration). Anyone else, including PMS_USER, is refused. See README.md § How authentication works in this module.
