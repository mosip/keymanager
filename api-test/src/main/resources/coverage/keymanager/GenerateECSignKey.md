**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Creates (or returns) an elliptic-curve signing key for an application — the kind of key used to sign JWTs and verifiable credentials with modern, compact signatures. The caller names the application and which curve it wants, and asks for either a signed certificate or a certificate signing request (CSR). The first call for an application and curve generates the key; later calls return the existing key unless the caller forces a new one.

**Request & response**

The path ends in the object type wanted: `CERTIFICATE` or `CSR` (upper or lower case). The body uses MOSIP's standard envelope:
```json
{
  "id": "io.mosip.keymanager.generateECSignKey",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "applicationId": "RESIDENT",
    "referenceId": "EC_SECP256R1_SIGN",
    "force": false,
    "commonName": "www.mosip.io"
  }
}
```
`applicationId` is required, must have a key policy and cannot be `ROOT`. `referenceId` picks the curve and must be one of `EC_SECP256R1_SIGN` (P-256), `EC_SECP256K1_SIGN` (secp256k1) or `ED25519_SIGN` (Ed25519). `force` = true asks for a new key. The certificate subject fields (`commonName`, `organizationUnit`, `organization`, `location`, `state`, `country`) are optional.

On success the response carries `certificate` (for `CERTIFICATE`) or `certSignRequest` (for `CSR`), both PEM text, plus `issuedAt`, `expiryAt` and `timestamp`:
```json
{
  "response": {
    "certificate": "-----BEGIN CERTIFICATE-----\n...",
    "certSignRequest": null,
    "issuedAt": "2026-11-10T10:00:00",
    "expiryAt": "2029-11-09T10:00:00",
    "timestamp": "2026-11-10T10:00:00"
  },
  "errors": null
}
```
Failures come back in `errors[]`, e.g. `KER-KMS-030` (reference ID not an EC sign type), `KER-KMS-002` (no key policy), `KER-KMS-005` (invalid request or object type).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration) — the same users who may read certificates. Anyone else is refused. See README.md § How authentication works in this module.
