**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Retires the current key of an application's reference ID before its normal expiry date — for example when a key is suspected to be compromised. The key is not deleted: it is marked as expired, so data already protected with it can still be handled, while the next request for that reference ID's certificate gets a freshly generated key. Master keys (empty reference ID) and the key manager's own signing key (`KERNEL` + `SIGN`) cannot be revoked here.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "applicationId": "REGISTRATION",
    "referenceId": "1001_1001",
    "disableAutoGen": false
  }
}
```
`applicationId` and `referenceId` are required and must not be empty. `disableAutoGen` is optional and currently has no effect.

On success:
```json
{
  "response": { "status": "Key Revoked", "timestamp": "2026-11-10T10:00:00" },
  "errors": null
}
```
Failures come back in `errors[]`, e.g. `KER-KMS-005` (missing or empty field, unreadable request), `KER-KMS-021` (revocation not allowed for KERNEL + SIGN), `KER-KMS-003` (no current key for that app ID and reference ID — also returned for an unknown app ID or a key already revoked).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
