**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

When `zkEncrypt` protects resident data, it also hands back the random key it used, encrypted for the ID Authentication (IDA) service's certificate. This endpoint takes that IDA-encrypted random key and re-encrypts it with the key manager's own zero-knowledge master key — the form in which the key manager stores its random keys. It lets a service that holds data plus an IDA-encrypted key bring that key back into the key manager's own storage format, without the key ever appearing in plain text.

**Request & response**

There is no request body; the key is sent as a query parameter:
```
POST /v1/keymanager/zkReEncryptRandomKey?encryptedKey=<encryptedRandomKey from zkEncrypt, URL-encoded>
```
`encryptedKey` is required. It may hold several base64url parts joined with `.` (one per IDA certificate); the first part whose certificate thumbprint is known is used.

On success:
```json
{
  "response": { "encryptedKey": "<standard Base64 of the master-key-wrapped random key>" },
  "errors": null
}
```
Failures come back in `errors[]`: `KER-ZKC-006` (blank key, or no part matches an IDA certificate), `KER-KMS-005` (parameter missing), `KER-CRY-003` (not base64url).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.

<summary>Technical details (automation + verification notes)</summary>

- Handler: `ZKCryptoManagerController.zkReEncryptRandomKey` (ZKCryptoManagerController.java:110-119); roles from `mosip.role.keymanager.postzkreencryptrandomkey` (application-local.properties:180). The key travels in the URL, so it can appear in access logs.
- Service: `ZKCryptoManagerServiceImpl.zkReEncryptRandomKey` (:464-507). Matches the first 32 bytes of each part (certificate thumbprint) against `IDA`/`PUBLIC_KEY` key aliases, unwraps with `KeymanagerService.decryptSymmetricKey`, re-wraps with the `KERNEL`/`IDENTITY_CACHE` master key using AES/ECB/NoPadding (application-local.properties:104-108).
- The IDA key-alias list is cached in an instance field on the first call and never refreshed (:476-479) — see row _005.
