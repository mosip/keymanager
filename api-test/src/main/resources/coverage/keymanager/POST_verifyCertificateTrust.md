**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Answers one question: does this certificate chain up to a CA that MOSIP trusts for the given partner domain? It checks the certificate's signatures and validity against the CA and sub-CA certificates uploaded for that domain and returns true or false. It does not store anything and does not check whether the partner certificate itself was ever uploaded.

**Request & response**

```json
{
  "id": "string", "version": "string", "requesttime": "2026-11-10T10:00:00.000Z", "metadata": {},
  "request": {
    "certificateData": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----",
    "partnerDomain": "AUTH"
  }
}
```
On success:
```json
{ "response": { "status": true }, "errors": null }
```
`status` false means no valid chain was found (unknown CA, missing sub-CA, expired, forged signature, other domain). Bad input comes back in `errors[]` with HTTP 200: `KER-KMS-013` (not a certificate), `KER-PCM-011` (domain not allowed), `KER-KMS-005` (empty field or unreadable body).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, PMS_ADMIN and PMS_USER (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
