**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Signs a piece of data with the key manager's own "client crypto" signing key and returns the signature. Anyone can later check the signature with the public key from `POST /v1/keymanager/tpmsigning/publickey`, for example through `POST /v1/keymanager/csverifysign`. On a server pod there is normally no hardware TPM, so the service signs with a software RSA-2048 key it created on first use (local mode).

**Request & response**

```json
{
  "id": "string", "version": "string", "requesttime": "2026-11-10T10:00:00.000Z", "metadata": {},
  "request": { "data": "SGVsbG8gTU9TSVA" }
}
```
On success:
```json
{ "response": { "data": "<URL-safe Base64 signature>" }, "errors": null }
```
`data` is the content to sign, URL-safe Base64 encoded. The returned `data` is the signature (SHA-256 with RSA, 256 bytes), URL-safe Base64 without padding. Blank `data` gives `KER-KMS-005`; data that is not URL-safe Base64 gives `KER-CRY-003` (both HTTP 200).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
