**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Encrypts data for whoever owns a given public key — typically a registration-client machine (TPM or software key), or the key manager itself when the key comes from `POST /v1/keymanager/tpmencryption/publickey`. The server never needs the matching private key; only the key owner can decrypt. It does not store anything and does not check the key against any registry.

**Request & response**

```json
{
  "id": "string", "version": "string", "requesttime": "2026-11-10T10:00:00.000Z", "metadata": {},
  "request": {
    "value": "SGVsbG8gTU9TSVA",
    "publicKey": "<URL-safe Base64 public key>",
    "clientType": "LOCAL"
  }
}
```
On success:
```json
{ "response": { "value": "<URL-safe Base64 encrypted package>" }, "errors": null }
```
`value` (the data) and `publicKey` are required, URL-safe Base64. `clientType` (`TPM`, `ANDROID`, `LOCAL`) is optional, defaults to `LOCAL` (an X.509 RSA key), and a TPM-format key is recognised automatically. The result is one package: the AES key encrypted with the public key, then IV, AAD and the AES-GCM ciphertext — 316 bytes longer than the data with default settings. Encrypting the same data twice gives different results.

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
