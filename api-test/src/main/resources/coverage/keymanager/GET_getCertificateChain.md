**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Returns the full chain of trust for a key the key manager holds: the key's own certificate, the certificate that signed it, and so on up to the key manager's ROOT certificate, bundled together as one PKCS#7 (`.p7b`) file. A partner or another system can use it to check that a MOSIP certificate really comes from the MOSIP root, without fetching each certificate separately.

**Request & response**

A plain `GET` with query parameters:
```
GET /v1/keymanager/getCertificateChain?applicationId=REGISTRATION&referenceId=
```
`applicationId` is required; `referenceId` is optional (leave it out or empty for the master key).

On success:
```json
{
  "response": {
    "certificatesTrustPath": "-----BEGIN PKCS7-----\n...",
    "timestamp": "2026-11-10T10:05:00"
  },
  "errors": null
}
```
The same errors as getCertificate apply (`KER-KMS-002` unknown app ID, `KER-KMS-012` master key not generated, `KER-KMS-005` missing parameter). If the chain cannot be built up to a trusted ROOT, the call currently fails with an internal error (`KER-KMS-500`, row _006).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.

<summary>Technical details (automation + verification notes)</summary>

- Handler: `KeymanagerController.getCertificateChain` (KeymanagerController.java:299-308); roles from `mosip.role.keymanager.getcertificatechain` (application-local.properties:186).
- Service: `KeymanagerServiceImpl.getCertificateChain` (:1422-1436) calls `getCertificate`, then `KeymanagerUtil.getCertificateTrustPath` (KeymanagerUtil.java:742-781), a PKIX path build with revocation checks off.
- Trust anchors come from a cache (KeymanagerUtil.java:231-240, `getTrustAnchors` :697-740): ROOT certificates are anchors; every other master key (empty reference ID) and `KERNEL`+`SIGN` are intermediates. A master key created after the cache was loaded is not an intermediate until the cache refreshes.
