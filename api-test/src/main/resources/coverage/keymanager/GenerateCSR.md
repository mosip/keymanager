**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Produces a certificate signing request (CSR) for a key the key manager already holds, so that the key's certificate can be signed by an outside certificate authority. With no reference ID it uses the application's master key; with a reference ID it uses (and on first use creates) the key stored under that reference ID. It never hands out the private key — only the CSR, which contains the public key and the requested certificate subject.

**Request & response**

```json
{
  "id": "io.mosip.keymanager.generateCSR",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "applicationId": "PMS",
    "referenceId": "",
    "commonName": "www.mosip.io",
    "organizationUnit": "MOSIP-TECH-CENTER",
    "organization": "IITB",
    "location": "BANGALORE",
    "state": "KA",
    "country": "IN"
  }
}
```
`applicationId` is required and must have a key policy (and, for an empty `referenceId`, an existing master key). The subject fields are optional; missing ones take the service's configured defaults. Some combinations are refused: `KERNEL` with `IDENTITY_CACHE`, and any custom reference ID under `ROOT`.

On success the response carries the PEM CSR plus the key's validity dates:
```json
{
  "response": {
    "certSignRequest": "-----BEGIN CERTIFICATE REQUEST-----\n...",
    "issuedAt": "2026-11-10T10:00:00",
    "expiryAt": "2029-11-09T10:00:00",
    "timestamp": "2026-11-10T10:00:00"
  },
  "errors": null
}
```
Failures come back in `errors[]`, e.g. `KER-KMS-002` (no key policy), `KER-KMS-012` (master key not generated yet), `KER-KMS-016` (not allowed under ROOT), `KER-KMS-022` (CSR not allowed for this app ID and reference ID), `KER-KMS-005` (invalid request).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
