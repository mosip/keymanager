**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Creates a CBOR Web Token (CWT): a small signed token, the binary cousin of a JWT, used for example in QR-code credentials (including the Claim 169 identity format). The caller gives the claims as JSON (or ready-made Claim 169 data); the key manager adds issuer, subject, audience and validity dates and signs the result with a key it holds. `/cwtVerify` checks it.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "payload": "eyJhbnlLZXkiOiJUZXN0IEpzb24ifQ",
    "claim169Payload": "",
    "applicationId": "",
    "referenceId": "",
    "algorithm": "",
    "protectedHeader": {},
    "unprotectedHeader": {},
    "issuer": "mosip.io",
    "subject": "mosip.io",
    "audience": "",
    "notBeforeDays": 0,
    "expireDays": 30,
    "CWTId": "UUID"
  }
}
```
At least one of `payload` (base64url JSON whose fields become claims) or `claim169Payload` (hex) is needed. `applicationId`/`referenceId` choose the key; empty means KERNEL/SIGN. `notBeforeDays`/`expireDays` set when the token starts and stops being valid (configured defaults if left out); `CWTId` = `UUID` adds a random token ID.

On success:
```json
{
  "response": { "signedData": "d83dd28445a101390100a0...", "timestamp": "2026-11-10T10:00:00.000Z" },
  "errors": null
}
```
`signedData` is the CWT as a lower-case hex string. Failures come back in `errors[]`, e.g. `KER-JWS-102` (no payload), `KER-JWS-103` (payload not JSON), `KER-SIG-117` (negative days), `KER-JWS-108` (caller may not use this app's key), `KER-KMS-012` (no key yet).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN, RESIDENT and CREDENTIAL_ISSUANCE (default configuration). Anyone else is refused. An app's key policy can further limit which user names may sign with its keys. See README.md § How authentication works in this module.
