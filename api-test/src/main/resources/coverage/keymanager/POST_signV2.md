**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Signs raw data (not wrapped in a JWT) with a key held by the key manager and returns only the signature. It is used where a bare signature is needed — for example for verifiable-credential proofs that expect a multibase-encoded value.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "dataToSign": "eyJhbnlLZXkiOiJUZXN0IEpzb24ifQ",
    "applicationId": "",
    "referenceId": "",
    "responseEncodingFormat": "base58btc",
    "signAlgorithm": "PS256"
  }
}
```
`dataToSign` (base64url) is required. Empty `applicationId` means the KERNEL/SIGN key. `responseEncodingFormat` is `base58btc` (default, multibase with a `z` prefix) or `base64url`; `signAlgorithm` defaults to PS256.

On success:
```json
{
  "response": { "signature": "z3MvGc...", "timestamp": "2026-11-10T10:00:00.000Z" },
  "errors": null
}
```
Failures come back in `errors[]`, e.g. `KER-JWS-108` (caller may not use this app's key), `KER-KMS-036` (unknown encoding format), `KER-KMS-012` (no key yet), `KER-KMS-020` (signing not allowed for that app/reference pair), `KER-KMS-005` (missing field).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN, RESIDENT and CREDENTIAL_ISSUANCE (default configuration). An app's key policy can further limit which user names may sign with its keys. See README.md § How authentication works in this module.
