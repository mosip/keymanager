**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Returns the current public certificate of a key that the key manager holds for an application. With no reference ID it is the application's master key; with a reference ID it is the key kept under that reference ID (created, and signed by the master key, the first time that reference ID is asked for). Other systems call it to get the certificate they should encrypt data for or verify signatures with. It never returns a private key.

**Request & response**

A plain `GET` with query parameters:
```
GET /v1/keymanager/getCertificate?applicationId=REGISTRATION&referenceId=
```
`applicationId` is required; `referenceId` is optional (leave it out or empty for the master key).

On success:
```json
{
  "response": {
    "certificate": "-----BEGIN CERTIFICATE-----\n...",
    "certSignRequest": null,
    "issuedAt": "2026-11-10T10:00:00.000Z",
    "expiryAt": "2029-11-09T10:00:00.000Z",
    "timestamp": "2026-11-10T10:05:00.000Z"
  },
  "errors": null
}
```
Failures come back in `errors[]` with HTTP 200, e.g. `KER-KMS-002` (the app ID has no key policy), `KER-KMS-012` (the master key was never generated), `KER-KMS-003` (more than one current key), `KER-KMS-005` (the `applicationId` parameter is missing).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
