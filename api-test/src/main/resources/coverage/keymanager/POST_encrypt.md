**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Encrypts data with the key that belongs to an application and reference ID, so that only the key manager can later decrypt it (via `/decrypt`). Each call makes a fresh one-time AES key, encrypts the data with it, and locks that one-time key with the app's public key. If the reference ID has no key yet, one is created on the spot.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "applicationId": "REGISTRATION",
    "referenceId": "REF01",
    "timeStamp": "2026-11-10T10:00:00.000Z",
    "data": "aGVsbG8gd29ybGQ",
    "salt": "<optional, base64 12-byte IV>",
    "aad": "<optional, base64 additional authenticated data>"
  }
}
```
`applicationId`, `referenceId`, `timeStamp` and `data` (base64) are needed; an empty `referenceId` (the app's master key) is refused.

On success:
```json
{ "response": { "data": "<base64url ciphertext>" }, "errors": null }
```
Failures come back in `errors[]`, e.g. `KER-KMS-005` (missing field), `KER-CRY-003` (not base64), `KER-CRY-011` (master or signing key named), `KER-KMS-002` (unknown app ID), `KER-KMS-012` (app master key not generated yet).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). Anyone else is refused. See README.md § How authentication works in this module.
