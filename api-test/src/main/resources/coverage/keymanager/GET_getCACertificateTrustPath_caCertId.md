**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Gives back a CA or sub-CA certificate that was uploaded to the key manager together with the certificates above it, up to its root, as one PKCS#7 ("p7b") bundle. Partner administrators use it to download the full trust chain of a CA so they can install it elsewhere or check it by hand. A root CA comes back on its own.

**Request & response**

A plain `GET` with the CA certificate's ID in the path (the `certId` that getCaCertificates lists):
```
GET /v1/keymanager/getCACertificateTrustPath/1f2e3d4c-....
```
On success:
```json
{
  "response": {
    "p7bFile": "-----BEGIN PKCS7-----\nMIIG...\n-----END PKCS7-----",
    "timestamp": "2026-11-10T10:05:00.000Z"
  },
  "errors": null
}
```
Failures come back in `errors[]` with HTTP 200: `KER-PCM-010` (blank ID), `KER-PMS-019` (no CA certificate with that ID).

**Who can call it**

Only PARTNER_ADMIN (default configuration) — not GLOBAL_ADMIN or PMS_ADMIN. Anyone else is refused. See README.md § How authentication works in this module.

<summary>Technical details (automation + verification notes)</summary>

- Handler: `PartnerCertManagerController.getCACertificateTrustPath` (PartnerCertManagerController.java:210-219); roles from `mosip.role.keymanager.getcacertificatetrustpath` (application-local.properties:182).
- Service: `PartnerCertificateManagerServiceImpl.getCACertificateTrustPath` (:777-806). The chain is built with PKIX against the trust store of the certificate's own partner domain; the result is cached per domain + thumbprint for `mosip.kernel.partner.certificate.chain.cache.expire.inMin` (default 1440 minutes).
- The upload call does not return the new `certId`; tests must look it up with getCaCertificates (or in `keymgr.ca_cert_store`).
