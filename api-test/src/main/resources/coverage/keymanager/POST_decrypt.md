**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Turns data that the key manager's `/encrypt` endpoint encrypted back into the original bytes. Other MOSIP services use the pair to protect stored data: they encrypt with an app's key and later ask the key manager to decrypt, so the private key never leaves the key manager. Decryption is allowed only for app IDs that have a key policy, and only for the users that policy allows.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "applicationId": "REGISTRATION",
    "referenceId": "REF01",
    "timeStamp": "2026-11-10T10:00:00.000Z",
    "data": "<ciphertext returned by /encrypt>",
    "salt": "<optional, base64 IV used at encryption>",
    "aad": "<optional, base64 AAD used at encryption>"
  }
}
```
`applicationId`, `timeStamp` and `data` are required. `salt` and `aad` are needed only if they were given to `/encrypt`; if sent, they must not be empty.

On success:
```json
{ "response": { "data": "aGVsbG8gd29ybGQ" }, "errors": null }
```
`data` is the original content, base64url-encoded without padding. Failures come back in `errors[]`, e.g. `KER-KMS-005` (missing field), `KER-CRY-003` (not base64), `KER-CRY-012` (no key policy or user not allowed), `KER-KMS-024` (ciphertext belongs to another app), `KER-FSE-004` (ciphertext altered).

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN and RESIDENT (default configuration). On top of the role, the app's key policy decides who may decrypt: `NA` lets every caller through, otherwise only the listed usernames. See README.md § How authentication works in this module.
