**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Signs any data (JSON by default, other data when asked) and returns a JSON Web Signature (JWS). It is the more flexible sibling of jwtSign: the caller picks the signing algorithm, whether the data must be JSON, and whether the payload is base64url-encoded in the signature (RFC 7797 "b64" option). Used for verifiable credentials and other signed documents.

**Request & response**

```json
{
  "id": "string",
  "version": "1.0",
  "requesttime": "2026-11-10T10:00:00.000Z",
  "metadata": {},
  "request": {
    "dataToSign": "eyJhbnlLZXkiOiJUZXN0IEpzb24ifQ",
    "applicationId": "",
    "referenceId": "",
    "includePayload": true,
    "includeCertificate": true,
    "includeCertHash": false,
    "certificateUrl": "",
    "validateJson": true,
    "b64JWSHeaderParam": true,
    "signAlgorithm": "PS256"
  }
}
```
`dataToSign` (base64url) is required; `validateJson` should always be sent (row _006). An empty `signAlgorithm` picks PS256, or ES256/ES256K/EdDSA for the matching EC/Ed25519 reference IDs. With `b64JWSHeaderParam` false (the default) the header says `"b64": false` and the raw decoded data is signed.

On success:
```json
{
  "response": { "jwtSignedData": "eyJ4NWMi...", "timestamp": "2026-11-10T10:00:00.000Z" },
  "errors": null
}
```
Failures come back in `errors[]`, e.g. `KER-JWS-108`, `KER-JWS-103`, `KER-KMS-012`, `KER-KMS-020`, `KER-KMS-005`.

**Who can call it**

ZONAL_ADMIN, GLOBAL_ADMIN, INDIVIDUAL, ID_AUTHENTICATION, TEST, REGISTRATION_ADMIN, REGISTRATION_SUPERVISOR, REGISTRATION_OFFICER, REGISTRATION_PROCESSOR, PRE_REGISTRATION_ADMIN, RESIDENT and CREDENTIAL_ISSUANCE (default configuration). An app's key policy can further limit which user names may sign with its keys. See README.md § How authentication works in this module.
